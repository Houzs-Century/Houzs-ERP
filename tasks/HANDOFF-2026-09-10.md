## 0. Where this sits

The ERP writes documents back into the licensed AutoCount book through
`scm.autocount_outbox`; a five-minute cron drains it. A document the composer
cannot express is written as a `skipped` row and **stays there** — no route
re-attempts it. This session was about emptying that backlog.

Read `docs/modules/autocount-writeback.md` before touching any of it. The
sections dated 2026-09-09 and 2026-09-10 are this work.

## 3. The two things worth remembering

**A rename in the ERP is a PRICE CHANGE.** Shortening the stored special-order
text was built, planned against production, and abandoned: `variants.specials` is
priced BY NAME (`findOption`, "Unknown picks contribute 0") and `recomputeOneLine`
runs on save. Everything now happens **at the moment of sending** and the ERP
keeps every word. `docs/bugs/0770`.

**A mirrored sofa passes every check.** Grouping a sofa's scattered pieces by the
book's own `DtlKey` was the right fix — and composing them in the ERP's INSERTION
order round-trips perfectly while writing `2ER + 1EL` where the book says
`1EL + 2ER`: the same pieces, the opposite sofa, and nothing downstream catches
it. The arrangement therefore comes from the book, and only money, warehouse and
dates come from the ERP rows. There is a test whose only job is to catch this.
`docs/bugs/0776`.

## 4. Why two counts went UP

**Line identity 3 -> 5** and **FAILED 1 -> 4** are not new damage.

- Three of the four failures are the HOST refusing a rebuild:
  *"has at least one line already transferred in AutoCount, so its details cannot
  be rebuilt"*. That guard is working; **nothing was written**. It means the
  re-queue tool always chooses a REBUILD, and these three documents need a plain
  keyed edit instead — which is what saving the document in the ERP composes.
- The line-identity documents are new saves that arrived during the session.

## 6. The tools, and what each answers

| run | question |
| --- | --- |
| `autocount-outbox-health.yml` | is anything stuck, and in which class |
| `autocount-held-back.yml` | WHICH document, and is it the one you think |
| `sofa-refusals.yml` | would ANY spelling let this sofa through |
| `too-long-for-the-book.yml` | the exact text that is over the column |
| `requeue-autocount-skipped.yml` | ask again — **DRY RUN by default**, `apply=1` to write |

All read-only except the last. The re-queue's dry run executes the real enqueue
and records the write instead of performing it, so it can only disagree with
APPLY about whether the row lands.
