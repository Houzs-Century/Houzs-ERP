# 陈列室的货能不能卖 —— 请老板选一个做法

**这是一个生意上的决定，不是程式的 bug，所以不会自己动手改。**
量出来的证据在 `docs/bugs/0682-*`，probe run **34173822315**（2026-09-08 08:36）。

---

## 1. 事情是什么（白话文）

割接的时候，我们把账本里陈列室的沙发**原样搬进来了，没有加任何标记** —— 照老板的规矩：

> 你换不一样就代表我们的数据从 autocount 搬过来的就不一样了啊

这是对的。**「完整的数据 + 我们的规则」**，规则要写在规则那一层，不是改一行搬进来的数据。

但这样就剩下一个从来没人问过的问题：**站在陈列室的货，系统会不会拿去答应客人？**

量完之后，答案分两半：

- **现在没有出事** —— 全公司**没有一张单**的货是指去陈列室的（0 张），
  所以**今天没有任何一张单**是靠陈列室的货说「有货」的。
- **但门是开着的** —— 九个「不卖货的仓库」里站着 **1,897 件货**，
  其中 **1,642 件是「随便谁指过来就能卖」那一类**。
  九个仓库**全部**都出现在开单的仓库下拉选单里，改一下就指过去了。

**那 26 张陈列沙发本身是安全的（PROVEN）**：沙发要变「有货」，一定要靠它自己那张采购单的
批号，陈列品没有采购单就没有批号 —— 量出来 17 个批次**全部**没有批号，
**沙发可见数量 = 0**。所以沙发一张都盖不到。

**真正要小心的不是沙发，是摆在沙发旁边的枕头。**

| PG DISPLAY | 槟城陈列室 | 530 | 447 |

| KELANA.J SHOWROOM | 格拉那再也 AKEMI | 58 | 48 |

**两件当初没想到的事：**

1. **最大的一堆不是陈列室，是 C&C（展销会）的 664 件** —— 比 KL 加槟城两间陈列室还多，
   而且 100% 都是「能被卖掉」那一类。
2. **两个「维修仓」比陈列室更糟：56 件。**
   那些货**根本不在店里**，是送回原厂在修的。陈列品起码还摆在店里看得到，
   这批货是人不在场的 —— 但系统一样会拿去答应客人。

## 3. 外面正规的 ERP 怎么做

标准做法叫 **ATP（Available To Promise，可以答应客人的数量）**，
重点是：**「仓库里有几件」和「可以答应客人几件」是两个不同的数字。**

- **SAP** —— 陈列 / 样品 / 待检的货放在不算进 ATP 的储位；货还在帐上、还有价值，
  但接单的时候看不到。
- **Odoo / NetSuite** —— 一样，可以设定哪些地点算进「可承诺库存」。
- **AutoCount 本身没有这一层** —— 它只管「哪个 location 有几件」，
  所以这件事以前不会浮出来，是我们的 ERP 多了 MRP 才需要决定。

**我们现在的做法跟业界不一样**：我们只有一个数字，仓库里有就等于可以卖。

## 4. 三个做法

### 做法 A —— 分配库存的时候跳过这九个仓库（**建议这个**）

- 系统里**本来就有**这个标记（`warehouses.type` = display / showroom / service），
  「呆滞库存」那张报表**已经在用了** —— 就是老板讲过的那句
  「它明明是 showroom 的 display 啊」。**只有分配库存那段程式从来没看过它。**
- **而且标记是填好的**：九个仓库**九个都有**正确的类型（量过了，不是假设）。
  所以改完马上生效，不用先去补资料。
- 要改的：分配库存的地方多看一眼这个标记。**动一个地方，不动任何一行搬进来的资料。**
- 代价：以后要卖陈列品，**要先开一张调拨单**把货从陈列室转去卖货仓库。
  多一个动作，但换来「卖掉的」和「还摆着的」分得清楚。
- 风险很低：**今天 0 张单指着这些仓库**，所以改下去不会有任何一张现有的单从「有货」
  变「没货」。这是最好的时机 —— 越晚改，动到的单越多。

### 做法 B —— 只在开单画面上不给选陈列室

- 最省事，但**挡不住**：用汇入、程式、API 写进去的单照样绕过去，
  而且以后每加一个新画面就要记得再挡一次。
- **治标不治本**，只能当临时措施，不该当作最终方案。

### 做法 C —— 什么都不改，陈列品就是可以卖

- 零成本。如果生意上本来就会把陈列品直接卖给客人（家具/床垫店很常见的「样品价」），
  那现在这样就是对的。
- 但**维修仓那 56 件挡不掉** —— 那批货是真的不在店里，答应了就出不了货。
- 就算选 C，也建议至少把两个 SERVICE 仓排除掉。

---

## 5. 建议

**选 A**，理由三个：

1. **现在改代价最小** —— 今天 0 张单受影响，以后只会越来越多。
2. **不用先补资料** —— 九个仓库的类型都已经填好了（量过）。
3. **不动搬进来的资料** —— 完全符合老板的规矩，规则写在规则层。

**如果老板本来就有在卖陈列品**，A 还是对的：多开一张调拨单而已，
而且这样帐上才看得出来「这件陈列品已经卖掉了」。

**要是只想先挡最危险的**，那就先把 **KL SERVICE + PG SERVICE** 两个维修仓排除掉
（56 件），陈列室那七个之后再说 —— 这是 A 的缩小版，改的地方一模一样。
