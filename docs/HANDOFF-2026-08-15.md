## 6. Eight traps this session paid for, that are not in any gate

1. **`git stash pop` with a clean tree pops SOMEONE ELSE'S stash.** `git stash`
   on a clean tree saves nothing, so the following `pop` restored an unrelated
   entry from another branch and conflicted a file. Nothing was lost — a
   conflicted pop keeps the stash — but check `git stash list` before either.

2. **`echo "pushed"` after a `git push` prints on failure too.** A push was
   rejected as non-fast-forward and the echo still claimed success. Verify by
   re-reading the remote: `git fetch && [ "$(git rev-parse HEAD)" = "$(git rev-parse @{u})" ]`.

3. **A shell ate a `\b` and invalidated a red proof.** A guard was "proven red"
   against a mutation that never applied as intended; the guard would have missed
   the real thing. Apply proof mutations by EDITING THE FILE, never through a
   shell one-liner, and make the mutation script exit non-zero if the
   replacement did not apply.

---

4. **A checker that answers a DIFFERENT question reads exactly like a pass.**
   Moving a 108-column SELECT list, a raw-text comparison said "different" and
   was counting the added `export` keyword and the indentation. Comparing the
   COLUMN SET said 108 = 108, none lost, none added. Ask what your check would
   ALSO be true of. My own orphan-script scan made the same mistake in the other
   direction: it reported 9 "file not found" that were really "my path resolver
   could not find them".

5. **A red proof that produces a SYNTAX ERROR is not a red proof.** Mutating a
   mirror to prove its guard fires produced a parse error, and vitest reported
   `Tests no tests` — the guard died with the thing it guards. Run `node --check`
   on the mutated file and confirm it is still VALID before believing the red.

6. **Backticks in a `git commit -m "..."` are command substitution.** A commit
   message lost the word `item_categories` entirely — the shell ran it and
   substituted the empty output. Use `git commit -F -` with a quoted heredoc for
   anything containing backticks.

7. **`gh` outside a git repo returns EMPTY, and empty is not "still open".** A
   watcher looping from a worktrees PARENT directory read every merged PR as
   unmerged, because `gh pr view` could not resolve the repo and the loop treated
   `!= MERGED` as open. Pass `-R owner/name`, and report "could not read" as its
   own outcome rather than folding it into a real state.

8. **Write a file-size ceiling in the GATE's unit.** `check-file-size` counts
   newlines (`split('
').length - 1`); a hand-count that includes the trailing
   line reads one higher. Setting it the other way passes, and leaves a phantom
   line of slack in a file whose neighbours were measured differently.
