## 5. Method notes — the reason several of the above exist

Seven mistakes this session; four were caught by the owner or by a tool, not by
me. The three that generalise:

1. **A query that traverses a link cannot audit whether the link is there.** The
   first duplicate check joined on `so_item_id` and so was blind to exactly the
   rows it existed to find. Audit by the header, or by the absence.
2. **A convenient signal is not the fact.** `total_cost_sen = 0` was used to mean
   "consumed no lot" — but the cancel path zeroes it deliberately, so it also
   means "was cancelled". Reading `inventory_lot_consumptions` directly was the
   answer. Same shape as `.catch(() => {})` meaning "ignore network errors", not
   "ignore errors".
3. **`git add -A` in a repo with other work in flight stages whatever is there.**
   It happened twice; the second time an unrelated half-finished `MobileScan.tsx`
   reached production on the sales team's daily screen. Stage the files the change
   needs; read `git status` before committing.

And the standing one from CLAUDE.md that was not honoured: **for UI changes, test
in the browser before claiming success.**
