### 2.2 Five sofa SKUs — quantity, value AND MRP all wrong

```
OMMBUC-1A(LHF) · OMMBUC-2A(RHF) · TRION-(K) bf-17 · XAMMAR-1A(LHF) · XAMMAR-2A(RHF)
movement ledger -1 (NEGATIVE on hand)   lot ledger 0
```

Variant key drifted: goods received under one key and shipped under another —
`|totalheight=24"` appended on one side, and a curly `”` mixed with straight `"`.
MRP keys buckets by `item_code + variant key`, so it sees ONE product as TWO:
stock on one, demand on the other.

**Not caused by this week's work.** Documented class —
`docs/inventory-ledger-divergence-coe.md`. `MODE=relabel` currently plans 0 and
refuses honestly.

**The two blocking questions are ANSWERED — read `backend/src/scm/shared/variant-key.ts`:**

1. **`totalheight` BELONGS in the key.** `ATTRS_BY_GROUP.bedframe` is
   `['fabricCode', 'gap', 'divanHeight', 'legHeight', 'totalHeight']`. So the key
   WITH `|totalheight=24"` is canonical; the one without it is the legacy,
   incomplete form. Relabel should move rows ONTO the totalheight key, not off it.
2. **The curly quote is `norm()` not touching quote glyphs.**
   `const norm = (v) => String(v).trim().toLowerCase()` — trim and lowercase only,
   so a curly and a straight inch mark are two different buckets. The glyph
   arrives from whatever form wrote the line.

The file states this session's exact cause in its own comment:

> Historical rows are NOT migrated — pre-fix stock may sit under legacy keys

The key builder was corrected at some point and the existing rows were left
behind. These five buckets are that sentence.

**Go-forward fix, with a trap.** Normalising curly quotes inside `norm()` stops
NEW drift — but it also changes the computed key for every existing value that
contains one, i.e. it moves stock into a different bucket and can create fresh
drift while closing the old. Measure first: count the rows whose key contains a
curly quote, then decide whether the code change ships WITH a data migration or
not at all. Do not ship the one-line `norm()` change on its own.

**The measurement now exists — but has NOT been run yet.**
`backend/scripts/check-variant-key-drift.mjs` + Actions → **Variant key drift
check (read-only)**. It discovers every variant-keyed table from
`information_schema` (so a new table cannot fall out of the count) and reports,
per table: rows and distinct keys containing a curly quote, and every MERGE
GROUP — a normalised key that today maps to more than one raw key, with the raw
keys printed. A group whose keys are the same attributes in two glyphs is drift
being healed; a group whose keys are genuinely different attributes is stock
about to be fused wrongly, and the counts alone cannot tell them apart.

**It cannot be dispatched until it is on `main`** — `workflow_dispatch` only
offers workflows on the default branch. Merge the branch, run it, read the merge
groups, and only then decide about `norm()`.

### 2.3 OCR must pick the nearest item from the picker — DONE 2026-08-05

`frontend/src/vendor/scm/lib/sku-nearest-match.ts`. `scan-prefill` had ONE
case-insensitive equality against the catalog, so `BOOQIT 1A (LHF)` against a
catalog holding `BOOQIT-1A(LHF)` resolved to nothing and the operator re-picked a
SKU the reader had, in substance, already found.

`findNearestSku` tries four tiers: exact → normalised (punctuation and spacing
stripped) → unique prefix (a dropped suffix) → bounded Levenshtein within a
length-scaled budget. **Every tier yields exactly one candidate or none.** A
wrong SKU orders the wrong furniture, so ambiguity is always a refusal: `BOOQIT`
alone spans 1A(LHF)/2A(RHF)/CNR and is refused; a code equidistant from two SKUs
is refused; under 5 characters the distance budget is zero. Because it refuses on
ambiguity it can only turn a NO-match into a match, never one match into another.

12 unit tests over real 2990 catalog shapes. `matchSource` rides on the
reconciled line so a surface that auto-commits the SKU can flag a near match;
mobile does not auto-commit (it seeds the line NAME and leaves the picker to the
operator), so the gain there is real SKU names instead of raw handwriting.

### 2.5 Documentation debt — DONE 2026-08-05

`docs/modules/delivery-return.md` and `docs/modules/purchase-return.md`, written
from the code. The two things each guide leads with, because they are what will
catch someone out:

- **Delivery Return** — `resyncInventoryForReturn` is a delta walk to a TARGET,
  not an incremental adjustment. That is what makes edits and cancels safe, and
  what a stray `+qty` write beside it would break. A CANCELLED return targets
  zero. SERVICE lines never write IN, on create or in the resync. The resync is
  best-effort, so a failed one is silent.
- **Purchase Return** — the DRAFT stage was removed: a PR is CREATED as POSTED
  with inventory OUT already written, so `/:id/post` survives only as an
  idempotent back-compat path and making it a real transition would double-debit.

Both note that the nullable link column is legitimate (goodwill / ad-hoc lines)
and must not be made NOT NULL — the guard is what stops it being a bypass — and
that neither module has a mobile twin, which is worth stating in a repo whose
standing rule is that the two surfaces change together.

## 5. Method notes — the reason several of the above exist

Seven mistakes this session; four were caught by the owner or by a tool, not by
me. The three that generalise:

1. **A query that traverses a link cannot audit whether the link is there.** The
   first duplicate check joined on `so_item_id` and so was blind to exactly the
   rows it existed to find. Audit by the header, or by the absence.
2. **A convenient signal is not the fact.** `total_cost_sen = 0` was used to mean
   "consumed no lot" — but the cancel path zeroes it deliberately, so it also
   means "was cancelled". Reading `inventory_lot_consumptions` directly was the
   answer. Same shape as `.catch(() => {})` meaning "ignore network errors", not
   "ignore errors".
3. **`git add -A` in a repo with other work in flight stages whatever is there.**
   It happened twice; the second time an unrelated half-finished `MobileScan.tsx`
   reached production on the sales team's daily screen. Stage the files the change
   needs; read `git status` before committing.

And the standing one from CLAUDE.md that was not honoured: **for UI changes, test
in the browser before claiming success.**
